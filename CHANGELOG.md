# Muse Motion Changelog

## v1.7 - 2026-11-15

Fourth independent developer audit (of v1.5; 32 items). Every item was re-verified against v1.6 before fixing - all 32 were confirmed in substance (two with narrowed scope, noted below) and are fixed here. The audit's headline stands: burned captions were not safe for client work, and now the timing defect behind that verdict is gone by construction.

- C-01 (Critical) caption timing is now ANCHORED to the speech. build_captions.py no longer tiles a block's window proportionally to character counts - that model let a cue appear seconds before its words (reproduced at 3.9s early on a synthetic fixture; 7.27s on the auditors'). Each cue now starts at most 0.3s before its own first word (and never before the previous cue ends) and ends no earlier than its last word + 0.2s, extended only by the reading-speed limit and a 0.7s floor. Over-speed cues are still declared as bursts on their FINAL timings.
- H-04 captions can no longer run past the timeline: build_cues takes the duration, clamps cue ends to it, drops words that start past it, and declares both counts in captions.json (cues_clamped_to_duration, words_dropped_past_duration) and in the build output. check_captions.py gains the missing form checks (M-05): more than 2 lines per cue and backwards cues (end <= start) are now errors. Threshold alignment (L-01): the checker's minimum-duration warning now uses the engine's 0.7s floor; the remaining severity difference (checker errors on over-speed, the engine declares bursts) is documented in both tools as a deliberate sidecar-vs-burned distinction.
- N-01 (High) sample_frames.py deletes NOTHING but its own: stale cleanup now removes only the files recorded in the folder's previous frames_manifest.json. The v1.5 glob deleted any frame_*.png in the output folder - including a render's frame_%04d.png sequence (all 10 planted files reproduced deleted). A planted foreign file now survives byte-identical (V01), and the tool's own stale frames are still cleaned (N08, via the manifest).
- H-01 validator: the burned-captions render gate now compares the captions.json CONTENT against the directive - language, style, word_highlight and canvas must match, so a stale or wrong-language build fails the gate instead of rendering.
- H-02 peak_guard preserves every stream: the remux maps all streams and chapters, copies everything except audio, and re-encodes only the audio - losslessly for PCM/FLAC sources, otherwise AAC at the source's bitrate floored at 192k and capped at 384k. (Regression found by the shipped suite while landing this: flooring at a probed 126k made a hot sine overshoot to +2.52 dBTP after the cut - P02 caught it; the floor is 192k because encoder overshoot grows as bitrate falls.) The fixed multi-stream fixture keeps 2 audio + subtitle + video (V06).
- H-03 the documented caption burn command no longer breaks ffmpeg: the reference told users to add -framerate before the concat input, which the concat demuxer rejects ("Option framerate not found", reproduced). The doc now states timing comes from the manifest durations; a regression case runs the documented command verbatim (V16).
- H-05 portrait captions clear the platform UI band: the default bottom margin at 1080x1920 rises from 300px (inside the TikTok band the skill's own reference documents) to 460px, scaled by height, and the panel width budget now guarantees the panel fits the canvas (text width leaves padding + 24px edges). Reels' ~35% ads exclusion stays an explicit --bottom-margin choice, now documented in SKILL.md.
- N-02 16-bit alpha depth fallback fixed (this CORRECTS the v1.5 changelog, audit ND-01: the F0-6 false-fail was recorded as "NOT reproduced" because only FFV1 was tested - it reproduces with the PNG codec, whose bits_per_raw_sample is N/A and whose rgba64be name has no pNN suffix). bit_depth_of now maps 64/16-suffixed format names to 16 bits; a genuinely half-transparent PNG-codec file passes alpha_content on the 65535 scale (V02), and the 8/12/16-bit cases still judge correctly.
- N-03/ND-03 the colour route has a fourth case: UNTAGGED sources (most phone, screen and generated media) are treated as BT.709 with the assumption recorded in the brief and the tags completed on encode - with the explicit reasoning for why this is not the forbidden relabel (no existing tag contradicts the pixels), plus a stop rule if the picture looks like disguised HDR. SKILL.md intake matches.
- N-04 faststart_required: true on a container with no moov atom (WebM/MKV) now FAILS the QC gate with a named check instead of passing silently.
- M-01/M-08 build_captions validates its input: malformed JSON, missing/non-numeric word times and backwards words are clean exit-2 errors (no tracebacks), out-of-order words are sorted with a note. transcribe.py wraps model/ffmpeg failures the same way.
- M-02 Roman Urdu coverage is gated: below 60% dictionary coverage the build fails with instructions (extend the dictionary or --force, on the record); the 85% review line is unchanged.
- M-03 the language gate no longer trusts the Whisper label alone: the words' actual script is cross-checked (an "ur" transcript whose letters are not Arabic script is refused, and vice versa), --force remains the reviewed override.
- M-04 Urdu layout is measured, not factored: Nastaliq ink measured 87px tall where the old 1.9x factor allowed 66px, so lines overlapped and descenders crowded the underline. Lines now stack by measured ink height with a real gap; the rendered result was verified visually.
- M-06 tests: 17 new cases (V01-V17) cover every fix above, including the timing anchor, the burn command, the vertical margin measured from the rendered PNG, and transcribe's output location. M-07 transcribe.py's default output is now the current directory, not the source folder (V17).
- L-02 the English font is resolved by search (flag, env, per-OS standard locations) instead of one Linux-only path. L-03 Urdu builds refuse loudly when Pillow lacks libraqm, instead of rendering unshaped script.
- Docs (D-01..D-08, ND-02): README is current (v1.7, 81 cases); requirements.txt documents libraqm; SKILL.md drops the false "captions can never collide with protected regions" claim (safety is placement discipline + the PLACEMENT rule), scopes the Remotion-caption/VTT/cache text in the ffmpeg reference to what the tools actually do, and tightens the frontmatter trigger; the taxonomy playbook separates the Remotion page model from the skill-bar engine model (D-06); LICENSE carries the OFL carve-out for the bundled font (D-07); the peak_guard descriptions match the stream-preserving remux (D-05). D-08 is addressed in part: the trigger wording is tightened; SKILL.md's size is unchanged in substance because its rules are the product.
- Tests: 81 cases, all passing (including P02, which caught a real regression in this very fix round); the v1.0 auditors' suite still passes 18 of 18. skill.yaml and SKILL.md synchronised at version 1.7.

## v1.6 - 2026-11-15

Owner audit of the ISS documentary edit (the first full-length landscape delivery): the owner found fact cards parked directly above the caption band, and the self-audit found broken caption phrasing. All findings were reproduced before fixing; the fixes are in the engine and the validator, not just in that one video.

- Caption cue-group repairs in build_captions.py (owner audit: a one-word cue "routine." flashed for 0.7s, "space." likewise, and phrases split as "for the night / side" and "A city in / space."). Grouping now (a) swallows one short trailing word past the char budget when it completes a phrase - never across a sentence end, so a new sentence's first word is never swallowed; (b) merges orphan tail groups (a single word, or a group at or below 29 percent of the cue budget) into the previous group; (c) shifts a trailing function word (the, in, of, ...) into the next group so a cue does not end mid-phrase. The orphan threshold and merge cap are relative to --max-chars (2x budget = two rendered lines): the new K12 case exposed that an absolute 12-char threshold collapsed every group into one cue at --max-chars 20 - fixed before release, with the shipped ISS captions byte-identical before and after (SRT diff empty at the default budget).
- Rendered lines now respect the per-line character cap as well as the measured width, and two-line cues are length-balanced, so a repaired cue never renders as a full line over a stub ("...for the night" / "side" now renders "Giant batteries store / energy for the night side").
- Caption-zone placement rule (owner, from her own screenshot comparison): with burned/both captions, heading and fact cards belong in the top zone like a title card, never parked in the bottom zone above the caption band. validate_directive.py warns PLACEMENT when a beat layout's bottom edge enters the bottom 26 percent of the frame while captions are burned/both; the rule is documented in references/workflow-and-directive.md and SKILL.md. On the audited directive the warning fired for all 8 fact cards; after moving them to the top zone it fires zero times.
- Proof on the real delivery: the ISS documentary was re-edited end to end (cards top, captions rebuilt 84 -> 79 cues with every flagged phrase whole, BBC logo at 110.4-120.6s and "Part X" corner text at 20.4-30.6s delogo-covered after dense corner sampling, end card hold extended, loudness compensated to land at -14.29 LUFS / -1.27 dBTP, QC PASS).
- Tests: 6 new cases (K12-K17) cover the orphan merge, the function-word shift, the compound swallow, the sentence guard, and the PLACEMENT warning both ways; the suite is 64 cases, all passing, and the v1.0 auditors' suite still passes 18 of 18. skill.yaml and SKILL.md synchronised at version 1.6.

## v1.5 - 2026-11-15

The six Phase-0 items from the v2.0 feature review, each verified live on v1.4 before fixing (four confirmed defects, one confirmed test-suite pattern, one not reproduced behaviorally). Only the confirmed scope was fixed.

- F0-1 faststart policy (CONFIRMED: a valid ProRes 4444 master failed the shipped alpha spec on moov_faststart): the moov check in qc_probe.py is now spec-driven via a new whitelisted spec key `faststart_required`. Web specs (youtube, vertical) set it true; the alpha-overlay spec sets it false; an unset spec defaults to required for .mp4/.m4v and not required for .mov. Documented as a delivery policy in the export/QC reference.
- F0-5 alpha specs (CONFIRMED: a valid VP9 alpha file failed the only shipped alpha spec on codec): new templates/delivery-spec-vp9-alpha-overlay.json (codec vp9, alpha required, no faststart). The ProRes spec is unchanged and stays strict single-codec, as the review recommended.
- F0-6 alpha bit depth (behavior NOT reproduced - 8-bit VP9, 12-bit ProRes and 16-bit FFV1 fixtures were all judged correctly): hardened anyway. bit_depth_of now trusts ffprobe's bits_per_raw_sample first and uses the pixel-format name only as a fallback, and the suite gained the 8-bit and 16-bit fixtures (N06/N07) the review asked for.
- F0-4 sampler (CONFIRMED live: stale frames survived a re-run, sheet was one long strip): sample_frames.py deletes the previous run's frame_*.png / contact_sheet*.png from the output folder before writing, and contact sheets are now grids (max 6 columns) paginated at 24 thumbs per sheet; the manifest lists every sheet in contact_sheets (contact_sheet keeps the first for compatibility).
- F0-2 colour (CONFIRMED gap: specs demanded bt709 tags but no conversion or unsupported path existed): references/ffmpeg-and-audio.md now documents the three-case route - BT.709 SDR proceeds; BT.2020 SDR is converted with the colorspace filter (command verified live: output probes bt709, frame statistics actually change, QC colour checks pass); PQ/HLG stops as unsupported on this toolchain (no zscale/libplacebo, colorspace build lacks smpte2084). Relabel-only fixes are explicitly forbidden, with the measured proof (a setparams relabel passes tag QC with unchanged pixels). SKILL.md intake carries the same rule.
- F0-3 honest tests (CONFIRMED pattern: 24 of 25 negative cases asserted exit codes only; one test bundled two defects; a skip counted as a pass): the strengthened cases now assert the exact named error/check (validator message substrings, FAIL <check> lines, checker messages), T16/T17 are split into separate cases, and the suite has a real SKIP state - R01 records SKIP when faster-whisper is unavailable and the summary reports passed/skipped/failed separately. Strengthening immediately exposed a live instance of the pattern: Q07 "zero-check spec FAILS" had never exercised the zero-check rule at all - the fixture's audio failed the DEFAULT loudness check first, so the case was green for an unrelated reason in every suite run up to v1.4. Q07 now uses a silent fixture on which no default check can fire, and asserts FAIL checks_executed by name. (This corrects the v1.4 verification report, which found no such case; the loudness default was the miss.)
- Tests: 10 new cases (N01-N10) cover every fix including the original reproductions; the suite is 58 cases. skill.yaml and SKILL.md synchronised at version 1.5.

## v1.4 - 2026-11-15

Caption engine added at the owner's request, with the house styles chosen by the owner from rendered samples: English and Roman Urdu use the skill-bar, Urdu script uses the Nastaliq bar, and both bars carry word-by-word amber highlighting of the spoken word (the owner's follow-up decision the same day).

- New scripts/build_captions.py: turns a word-timestamped transcript (transcribe.py output) into captions.json, captions.srt and an ffmpeg concat overlay layer (layer.ffconcat + per-word PNG states). Cue timing is reading-time based: words are grouped at natural pauses and each block's window is tiled proportionally at <=20 cps with a 0.7s minimum cue duration (water-filled inside the block). Cues that cannot fit because the speech itself is denser are declared as over-speed bursts in captions.json and warned in the self-check - on the real 9.4-minute reference video (fast conversational speech), 32 of 253 cues are bursts at 20.3-25.9 cps; the rest meet the limit. That is a property of the speech, reported rather than hidden.
- Languages: en (English transcript), ur (Urdu transcript, Nastaliq bar, RTL shaping via libraqm), roman (Urdu transcript transliterated with references/roman-urdu-dictionary.json; coverage percentage is computed and reported - 100% on the reference sentence; unknown words fall back to a character map and lower the score). The tool refuses cross-language requests (e.g. an English transcript for Urdu captions) because that is translation, not transcription.
- Bundled font: assets/fonts/NotoNastaliqUrdu.ttf (SIL OFL 1.1, licence file alongside) ships in the package ZIP so the Urdu style renders identically anywhere. Note: the GitHub mirror carries every text file but not the .ttf binary (the connector's push rejects binaries); a clone should fetch the font from the package ZIP or Google Fonts.
- validate_directive.py: optional top-level `captions` block (mode none|sidecar|burned|both, language en|ur|roman, style skill-bar|nastaliq-bar|karaoke, highlight word|none, source). Unknown keys/values are errors; deviating from the locked house style warns; at the approval gate, burned/both modes require captions.source to point at an existing captions.json. The directive template ships an example block (mode none).
- Docs: SKILL.md gains a Captions section with the locked styles and the language-honesty rule; the workflow reference builds captions in the transcription pass; the ffmpeg reference gains the layer-burning command. skill.yaml and SKILL.md synchronised at version 1.4.
- Tests: 11 new regression cases (K01-K11) cover the validator block, all three language builds, transliteration coverage, the translation refusal, word-highlight states and --no-highlight; the suite grows to 47 cases.

## v1.3 - 2026-11-15

Three workflow features added at the owner's request, each closing a gap that cost real time on the v1.1/v1.2 deliveries. The shipped regression suite grows to 36 cases (all passing); the v1.0 auditors' 18-case suite still passes 18 of 18.

- New scripts/peak_guard.py: measures the ENCODED file's true peak and, when it sits above the ceiling (default -1.0 dBTP), applies the smallest sufficient gain reduction as an audio-only remux (video stream-copied, never re-encoded) and re-measures. Why: loudnorm's linear pass promises the ceiling on PCM, but the AAC encode overshot it on three consecutive real deliveries (-0.95, -0.95 and -0.7 dBTP), each needing a manual fix pass. The guard reports before/after values and exits 0 (already within ceiling, or fixed), 1 (still above) or 2 (tool error). The QC contract now runs the guard before qc_probe.py.
- New scripts/transcribe.py: the transcription step is built into the skill. Local faster-whisper with word timestamps, writing the transcript JSON the directive design consumes. Audio is decoded to 16 kHz mono PCM with ffmpeg and fed to Whisper as a numpy array, sidestepping a PyAV build bug (av.open rejects the metadata_errors keyword) hit twice in production.
- New scripts/check_captions.py: the automatable part of AUD-27. Validates an SRT for line length (42), reading speed (20 cps), cue duration (warns under 0.8s / over 7s), timing overlaps (errors) and near-zero gaps, and WCAG contrast (at least 4.5 to 1) when the caption style colours are given. Caption wording and flash-rate judgement stay human, and the docs say so.
- Docs updated: workflow (transcription route), export/QC checklist (peak guard step, caption automation), ffmpeg reference (the AAC-overshoot explanation), SKILL.md and skill.yaml synchronised at version 1.3. requirements.txt now lists numpy explicitly (transcribe.py imports it directly).

Still open, deliberately: visual regression against approved edits, a bundled Remotion sample project, and multi-source timelines (AUD-23) - proposed for a later version, not silently dropped.

## v1.2 - 2026-11-15

Fixes from a third independent developer audit, this time of v1.1 (27 findings, AUD-01 to AUD-27). Every reproduced case was re-run against v1.1 before fixing; the package now ships its own regression suite (tests/test_muse_motion_regression.py, 28 cases, all passing) and the v1.0 auditors' 18-case suite still passes 18 of 18.

- validate_directive.py: source.kind video/audio/none unblocks the lyric and graphics-only routes, with timeline.duration_s for kind none and presenter treatments restricted to footage (AUD-01). Hold comparisons are frame-based, so exactly-legal 0.4s and 3.0s holds pass (AUD-06). Protected-region rule tightened to 10 percent of the region / 50 percent of the layout / any overlap on critical regions; the override must be the boolean true plus a non-empty overlap_reason and is always reported as a WARN and in --report (AUD-05). Key whitelists everywhere, beat id required and unique, version must be the integer 1, layout type-checked for all treatments (AUD-13). reveal_sync requires on_screen_copy (AUD-07). Reading-speed check: over 40 chars/s errors, over 20 warns (AUD-14; the warn tier exists because static cards show all lines at once, unlike sequential captions). Beat bounds and duration tolerance use the probed duration at about one frame; format.fps must match the source rate; canvas dimensions must be even; aspect tolerance 0.005 (AUD-15). approval.approved_by is required in strict mode (AUD-16 partial; content hashing deliberately not adopted - in this single-agent workflow the approval is the user's recorded decision, and a self-written hash would prove nothing). Transition set completed: slide-from-left, morph, match-cut, flip, clock-wipe (AUD-12). Exit codes are honest: missing file, unknown flags and missing ffprobe are tool errors (exit 2) (AUD-08). Relative source paths resolve against the directive folder, unhashable values get coded field errors, and --report writes the full result (AUD-26).
- qc_probe.py: spec keys are whitelisted and type-checked, unknown or null values exit 2 (AUD-10). fps tolerance 0.01 with VFR detection; a zero-check spec fails (AUD-10). moov check streams box headers, covers .mp4/.mov/.m4v, and a missing moov fails (AUD-09). Alpha accepts the full pixel-format set and the VP8/VP9 alpha_mode tag, and a content check decodes the alpha plane: it must drop below 90 percent of full scale somewhere (some ProRes encoders store opaque alpha at 3760 of 4095, so the exact-maximum test the audit proposed would false-fail on this toolchain; the 90 percent rule catches both) (AUD-04). New enforceable spec keys: pix_fmt, profile, field_order, colour tags, bit-rate range, audio codec and channels (AUD-11). Environment failures exit 2 with an ERROR report (AUD-08).
- sample_frames.py: handled errors with honest exit codes (non-media input exits 2, zero frames exits 1 with a manifest that lists nothing it did not make), --directive sampling of beat starts, reveal times and beat ends, and alpha frames composited on a checkerboard (AUD-19).
- ffmpeg reference: the timed PNG overlay uses -itsoffset instead of enable= (which silently skipped the entrance animation and froze the last frame), overlay uses eof_action=pass instead of shortest=1 (which truncated the video stream), audio maps are "0:a?", amix carries normalize=0, the loudnorm offset placeholder names target_offset, and frame rates are parameters, not hard-coded 30 (AUD-02, AUD-03, AUD-20).
- Docs: the four routes are defined with thresholds, the protected-region contradiction is removed, the element-family to treatment mapping is tabulated, the alpha route commands (ProRes 4444 and VP9) are written down, the 10le/12le note is corrected (the ProRes decoder reports 4444 as 12-bit regardless of encoder input), the canonical TSX snippet uses the CSS scale property instead of a composed transform string, and SKILL.md/skill.yaml descriptions are synchronised (AUD-17, AUD-18, AUD-22, AUD-24).
- Packaging: the regression suite ships in tests/, plus requirements.txt, a LICENSE, three delivery-spec templates, and a director-treatment template (AUD-21). README notes the Remotion company licence for larger for-profit teams.

Not fixed, deliberately:
- Multi-source directives and output-timeline mapping for pause-cut edits (AUD-23) stay a documented model limit; beat gaps now warn.
- Caption-limit, contrast and flash automation (AUD-27) remain checklist items for human/QC sign-off; reading speed is now automated in the validator.
- research-sources.md still summarises some standards through secondary summaries (AUD-25); primary links were added where a canonical URL exists.

## v1.1 - 2026-11-15

Fixes from two independent developer audits of v1.0. Every finding was re-verified against the v1.0 files before fixing; the auditors' own 18-case regression suite went from 16 failures on v1.0 to 18 of 18 passing on v1.1.

- validate_directive.py rewritten as a two-stage gate. Schema gate plus render-ready gate: approval must be approved with zero ambiguities (MM-001), source media must exist, probe as video, and match the declared duration (MM-002), layouts are required where the treatment needs them and must sit inside the canvas (MM-005), protected regions are collision-checked with an explicit 50 percent AABB overlap threshold and a documented override flag (MM-006), format, fps, aspect, treatment, role and transition tokens are validated against fixed sets (MM-007), malformed structures return handled INVALID errors with rule codes and never a traceback (MM-008), NaN and Infinity are rejected at parse time and booleans are never numbers (MM-009), and reveal_sync elements must be declared in on_screen_copy with times inside the beat (MM-010). A --draft mode validates schema only and never counts as render permission.
- qc_probe.py rewritten as an authoritative delivery gate (MM-003, MM-004, MM-011). It accepts a per-deliverable --spec, writes a machine-readable --report JSON, and exits 0 PASS, 1 FAIL, 2 tool error. Missing required audio fails as AUDIO_STREAM_MISSING, digital silence fails as AUDIO_SILENT, and loudness target and tolerance, true peak ceiling, dimensions, frame rate, codec, duration, required alpha pixel format, sample rate, and MP4 moov placement are all enforced.
- New scripts/sample_frames.py extracts deterministic hook, quarter, hero, three-quarter and end frames plus a contact sheet and manifest (partial automation for MM-012; visual judgement still requires human sign-off).
- SKILL.md gained standard YAML frontmatter for portable skill loaders (skill.yaml remains the Muse metadata source), the treatment list now matches the validator's 12 uppercase tokens exactly, and the role list matches the validator's lowercase tokens.
- ffmpeg reference gained the format=auto overlay chain with +faststart and a sidechaincompress voice-ducking pipeline.
- Remotion reference clarified that yuva444p10le (Remotion ProRes route) and yuva444p12le (ffmpeg prores_ks route) belong to different encoders, and gained a canonical TypeScript beat component plus a font-loading guardrail for RTL and Indic scripts.

Not fixed, deliberately:

- The connector links in SKILL.md use this workspace's standard paths. They are correct for Muse; other environments should map them to their own Drive and workspace tools (see the portability note in README.md).
- No complete Remotion sample project is bundled yet (MM-013 stays open as a known limitation). The gates, frame sampler, and real renders produced in the workspace are the current evidence; the package does not claim archive-level render proof.
- Automated visual regression beyond frame sampling (MM-012 remainder) stays a human sign-off step by design.
